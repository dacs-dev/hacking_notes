
# Registers
Dependiendo de la arquitectura utilizada, se te proporcionarán entre 8 y 32 variables globales de tamaño fijo para trabajar. Estas se llaman registros y cada nombre también depende de la arquitectura para la que estés programando o, en caso de ser un programa compilado, del compilador utilizado.  
El tamaño fijo también depende de la arquitectura de la CPU; normalmente es el mismo que el tamaño de palabra de la arquitectura. Aquí hay algunos ejemplos:

|Arquitectura|GPR|Tamaño GPR|
|---|---|---|
|x86 32-bit|8|32 bits|
|x86-64|16|64 bits|
|ARM64|31|64 bits|
|RISC-V 64|32|64 bits|
|RISC-V 32|32|32 bits|
|AVR|32|8 bits|

|Arquitectura|Tamaño GPR|
|---|---|
|AVR|8 bits|
|x86-32|32 bits|
|x86-64|64 bits|
|ARM64|64 bits|
|RISC-V 64|64 bits|

Uno de los registros más importantes es el **Program Counter (PC)**, que le dice a la CPU qué instrucción vamos a ejecutar a continuación. Cada vez que **ejecutamos una instrucción avanzamos** el program counter. Podemos entenderlo como que el PC contiene el valor de la línea a ejecutar.
### General Purpose Registers (GPRs)
Se refiere a un conjunto de registros de la CPU que pueden utilizarse para una amplia variedad de tareas, como almacenar datos, direcciones, resultados intermedios y realizar operaciones aritméticas y lógicas.
#### x86 (32-bit, IA-32)
 - **GPR (8):** `EAX, EBX, ECX, EDX, ESI, EDI, EBP, ESP`
##### Control básicos:
- `EIP` (program counter)
- `EFLAGS` (flags)
##### Segmentación:
- `CS, DS, ES, FS, GS, SS`
##### FPU/SIMD:
- - x87: `ST0..ST7` (stack de 8)
- MMX: `MM0..MM7` (alias sobre x87)
- SSE: `XMM0..XMM7` (en 32-bit normalmente 8 XMM)

##### GPR (16):

# Memory

Cuando hacemos programas complejos necesitaremos almacenar datos más grandes que el tamaño de los registros, como una lista o estructuras de datos.  
La CPU solo ve direcciones de memoria y en assembly no es como en C, donde un malloc te reserva la memoria que necesitas. Tendrás que gestionar directamente **stack, heap y segmentos**.

La memoria es básicamente un espacio lineal de direcciones donde cada dirección almacena 1 byte.
``` memory_directions
0x00000000  
0x00000001  
0x00000002  
```
##### HEAP
```nasm
; Paso 1: Asignar 8 bytes en el heap usando la syscall brk
mov rax, 12 ; syscall 12 = brk
mov rdi, 0 ; consultar dirección actual del heap
syscall 
; rax ahora tiene la dirección actual del heap (próxima disponible) 
; Supongamos que rax ya tiene un valor que queremos guardar
mov rbx, 0x12345678ABCDEF00 ; valor de ejemplo en rbx
mov [rax], rbx ; guardar rbx en la memoria asignada
```

##### STACK
Cuando hacemos programas complejos necesitaremos almacenar datos más grandes que el tamaño de los registros, como una lista o estructuras de datos.  
La CPU solo ve direcciones de memoria y en assembly no es como en C, donde un malloc te reserva la memoria que necesitas. Tendrás que gestionar directamente **stack, heap y segmentos**.

La memoria es básicamente un espacio lineal de direcciones donde cada dirección almacena 1 byte.
```nasm
sub rsp, 16    ; reservar 16 bytes
push rax ; Guarda el valor de rax en la pila
mov rax, 42 ; Usa rax para otra operación
pop rax ; Restaura el valor original de rax
```

# Control Flow
Se realiza mediante GOTOs, saltos, bifurcaciones o llamadas. El efecto de estas instrucciones es alterar directamente el program counter.  
Un **jump** es simplemente un GOTO incondicional.

La mayoría de las operaciones sobre registros, como suma y resta tienen el efecto lateral de alterar las **status flags**, como por ejemplo "el ultimo valor computado resulta en 0". Hay solo unas pocas status flags y normalmente viven en registros especiales (special registers).

Los **branches** son simplemente GOTOs que son ejecutados dependiendo del valor de una *status flag*. Por ejemplo "GOTO a esta direccion solo si la última operación aritmética ha resultado 0".
```nasm
mov eax, 5
cmp eax, 10        ; Compara eax con 10
jl  menor          ; Salta a 'menor' si eax < 10
mov ebx, 20        ; No se ejecuta si hay salto
jmp fin            ; Salto incondicional a 'fin'

menor:
    mov ebx, 30    ; Se ejecuta si eax < 10

fin:
    ; Continúa aquí   
```
Un **CALL** es un GOTO incondicional que pushea la siguiente dirección al Stack, con lo que una instrucción *RET* puede despues volver a donde la CALL dejó la ejecución del programa.
El flujo seria: - `call` guarda en el **stack** la dirección de la siguiente instrucción (la dirección de retorno).La función se ejecuta.`ret`:
- Hace `pop` de esa dirección del stack.
- La carga en el **Program Counter (RIP/EIP)**.
- La ejecución continúa ahí.
- RAX conserva el valor de retorno de la función.
```nasm
global _start  
  
section .text  
  
_start:  
call mi_funcion ; llama a la función  
  
; aquí ya volvió el control  
; rax contiene 5  
  
mov rdi, rax ; usar el valor de retorno como código de salida  
mov rax, 60 ; syscall exit  
syscall  
  
mi_funcion:  
mov rax, 5 ; valor de retorno  
ret
```
